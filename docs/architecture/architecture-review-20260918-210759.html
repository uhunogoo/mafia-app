A1 · Collapse the room-membership pipeline

Strong in-process

src/lib/identity.ts · src/components/Providers/PageProvider/ · src/components/CreateGame/ · src/components/Form/JoinForm/ · src/components/Room/RoomGuard/ · src/components/Providers/RoomConnectionProvider/

Problem: "a player attaching to a room" is implemented across five files; the host-claim invariant that prevents impersonation lives in both CreateGame and JoinForm.

Solution: one RoomMembership module owns resolve → claim → expose; storage becomes an adapter behind a seam.

  • locality: host-claim invariant in one place
  • tests hit one interface, in-memory adapter
  • leverage: RoomSidebar and PlayerGrid consume the same me
  • delete four shallow wrappers, gain one provider
  • no more NEXT_PUBLIC_COLYEUS_URL mock drift

A2 · Split lobby commands from the lobby view

Worth exploring ports & adapters

src/components/Room/RoomSidebar/RoomSidebar.tsx

Problem: RoomSidebar derives view state, branches host/guest, builds Colyseus message strings, and renders — interface ≈ implementation.

Solution: a useLobbyCommands(room) adapter names the protocol; LobbyPanel consumes the derived view.

  • interface shrinks to one prop
  • commands unit-test without Colyseus
  • rename 'setMaxPlayers' once, not five times
  • playersWord moves to a uk-plural adapter
  • leverage: night-phase UI reuses same commands

A3 · Source the client view from the server schema

Worth exploring cross-package

mafia-server/src/rooms/schema/MafiaState.ts · mafia-server/src/rooms/schema/enums.ts · src/components/Providers/RoomConnectionProvider/RoomConnectionProvider.tsx

Problem: the client redeclares MafiaStateView with role: string instead of Role — drift is silent.

Solution: hoist Role, GamePhase, Team and the Player shape into a shared @mafia-game/contracts package; both sides import.

Asks first: introduces a third package. Per boundaries.md, this means a new dependency and a workspace change — flag for confirmation before touching.
  • drift becomes a TS error
  • delete RoomPlayerView
  • leverage: phaseLabel becomes exhaustively typed
  • shared fixtures for both test suites

A4 · Reconcile the auth form boundaries

Speculative in-process

src/components/Form/LoginForm/ · src/components/Form/SignUpForm/ · src/components/Form/ForgotPasswordForm/ · src/components/Form/UpdatePasswordForm/ · src/components/Form/JoinForm/

Problem: five forms share a scaffold but pick two execution paths (server action vs Supabase client) inconsistently.

Solution: a useAuthAction hook + thin AuthForm; route each form to one adapter.

  • delete duplicate error blocks
  • force consistency on auth error UX
  • tests hit the adapter, not the form

Top recommendation

A1 · Collapse the room-membership pipeline

It's the load-bearing concept for the whole room flow — five files already collaborate on it and the host-claim impersonation guard is duplicated. One RoomMembership module gives you a single seam, a single adapter to test in-memory, and a vocabulary (me, hostClaim, token) the rest of the room UI can lean on. A2 and A3 both consume its interface; doing A1 first means they get cheaper.
