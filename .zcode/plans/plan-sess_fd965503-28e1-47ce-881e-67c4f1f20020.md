# Виправлення: кімната не повинна редіиректити на логін

## Проблема
Проксі (`src/lib/supabase/proxy.ts:55`) свідомо пропускає `/room*` без авторизації, і в застосунку вже є гост-флоу (`RoomGuard` → форма нікнейма → `createGuestIdentity` → `joinAsPlayer` у Colyseus). Але серверний компонент кімнати `src/app/room/[roomId]/page.tsx` викликає `requireUser()`, який для всіх без Supabase-сесії робить `redirect('/login')` — тож гостьове приєднання за посиланням фактично недосяжне. Ці два шари суперечать один одному.

## Зміни (тільки 1 файл)

**`src/app/room/[roomId]/page.tsx`:**
1. Видалити `requireUser()` та її виклик — разом з імпортами `redirect` (next/navigation) і `createClient` (supabase/server). Сторінка залишається async server component (`await params` потрібен для Next 16).
2. Видалити дубльований `<JoinForm />` (рядок 38 з коментарем `show for new player`) — `RoomGuard` вже показує оверлей з `JoinForm` для гравців без identity; зараз вони рендеряться обидва одночасно (один — розмитий, позаду другого).

Утримувачі рішень з узгодження:
- Проксі не змінюємо — виняток для `/room*` уже є.
- Хост, як і гості, вводить нікнейм (вибір користувача). `createHostIdentity` залишається поки мертвим кодом — можна підключити окремо потім.
- `identity.ts`, `join-form.tsx`, `room-guard.tsx` — без змін, вони вже реалізують правильний флоу.

## Результат
Будь-який користувач (залогінений чи ні), який відкрив інвайт-лінк `/room/{roomId}#token=...`, потрапляє на кімнату: фон видно розмитим, зверху — форма нікнейма; після введення — приєднання до лобі як гравець. Редірект на `/login` більше не відбувається.

## Перевірка
1. `npm run build` — переконатися, що немає помилок типів після видалення коду.
2. Ручна перевірка в браузері: запустити dev-сервер, відкрити `/room/<id>` без сесії → має рендеритися кімната з формою нікнейма, без редіректу (для цього не потрібен запущений Colyseus).
